# Leke Subword Tokenizer — Performance Benchmarks

Encode/decode throughput of Leke (Rust + PyO3) against the raw Hugging Face `tokenizers` library, both loading `models/bpe-16k/tokenizer.json`. Because both run the identical normalizer + Byte-Level BPE pipeline, the ratio column measures Leke's wrapper overhead.

Generated by `scripts/benchmark_throughput.py`.

## Setup

- **Input**: all 1,151 sentences of the held-out test splits (`data/splits/{twi,ewe,gaa,fat}/test.txt`), special tokens disabled.
- **Method**: median of 7 runs, each 20 passes over the input via `encode_batch` / `decode_batch`.
- **Threads**: Rayon pool pinned with `RAYON_NUM_THREADS` (1 thread, and all 8 logical cores).
- **Environment**: Linux x86_64, Python 3.12.3, `tokenizers` 0.23.3, extension built with `maturin develop --release`.

## Results

| Metric | Threads | Leke (Rust + PyO3) | HF `tokenizers` | Leke / HF |
| :--- | ---: | ---: | ---: | ---: |
| Encode (tokens/sec) | 1 | 238,339 | 242,679 | 0.98× |
| Encode (MB/sec) | 1 | 0.93 | 0.94 | 0.98× |
| Decode (sentences/sec) | 1 | 60,549 | 72,149 | 0.84× |
| Encode (tokens/sec) | 8 | 952,391 | 1,009,585 | 0.94× |
| Encode (MB/sec) | 8 | 3.70 | 3.93 | 0.94× |
| Decode (sentences/sec) | 8 | 235,201 | 166,065 | 1.42× |

Throughput depends on hardware and load; compare ratios rather than absolute numbers across machines. Consecutive runs on the same machine have varied by up to ~30%, so ratios between roughly 0.75× and 1.35× indicate parity.
